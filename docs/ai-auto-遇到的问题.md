# proxy-cache 以前踩过的坑（简单版）

这个项目是一个「帮大家下载 Docker 镜像的缓存站」：别人下过的镜像，它替你存一份，下次你再来就直接给，不用重新下载。

下面 22 条是它以前出过的问题，按「当时电脑报的什么错」分成 11 组。每条都写清楚三件事：**报的什么错**、**这句错话是什么意思**、**后来怎么修好的**。

状态只有两种：✅ 已修好、🟡 修好一半（这次没有 ❌ 还没修）。

## 目录

1. 镜像站发来的文件是坏的
2. 镜像站用不了（502 / 等不到回应）
3. 连接中途断掉了
4. 站点的安全证书不被信任
5. 没有权限读写缓存文件
6. 内存不够，缓存还被当成坏的删掉
7. 配置文件写错了，网址拼不出来
8. 该不该用缓存判错了（Range / 304 / 可变的标签）
9. 代码和打包本身有问题
10. 电脑环境坏了（挂着 Windows 磁盘 / `/dev/null` 被换掉）
11. 没有报错的问题（只是慢 / 看起来像坏）

## 1. 镜像站发来的文件是坏的

**当时电脑报的错：**
> `failed to copy: window size exceeded`
>
> `blob 回源内容摘要不符，拒绝写缓存`

**这句话是什么意思：**镜像站把坏文件当好文件发过来。我们下载完会自己算一遍「文件指纹」，和要的对不上就不许它进缓存；但已经直接发给用户的那些字节，收不回来了。

**对应的问题：**
- **#1 多源拼接坏字节**｜✅ 已修好 —— 坏字节被拼进了下载流；现在存之前反复核对。
- **#22 上游源回错内容**｜🟡 修好一半 —— 有的站会发错文件；存前查，直传那段还拦不住。

## 2. 镜像站用不了（502 / 等不到回应）

**当时电脑报的错：**
> `502 Bad Gateway`
>
> `net/http: timeout awaiting response headers`

**这句话是什么意思：**换了好几个镜像站都没成：要么直接回一句「502 打不开」，要么一直不回话，让下载工具干等到超时。

**对应的问题：**
- **#3 探测与扫描预算失准**｜✅ 已修好 —— 等源的时间算错，把能用的源提前判死。
- **#5 上游 401 与 HTML 毒化**｜✅ 已修好 —— 要登录就全失败，还把网页当内容存了。
- **#10 客户端零进度**｜✅ 已修好 —— 选源拖太久不回头，客户端一点进度都没有。

## 3. 连接中途断掉了

**当时电脑报的错：**
> `write: broken pipe`
>
> `stream error: stream ID 7; PROTOCOL_ERROR…`

**这句话是什么意思：**下载到一半连接就没了：有时是用户自己关掉了，有时是镜像站把连接掐断。结果都留下半截文件。

**对应的问题：**
- **#4 客户端断开语义**｜✅ 已修好 —— 断了还继续读上游一个多小时，白干活。
- **#9 单层大 blob 无并发**｜✅ 已修好 —— 一个大层只有一条连接，慢到 53KB/s。

## 4. 站点的安全证书不被信任

**当时电脑报的错：**
> `x509: certificate signed by unknown authority`
>
> `certificate is valid for *.linkease.net…`

**这句话是什么意思：**有的镜像站用的是自己签的证书，或者证书上写的名字和网址对不上，程序就不敢连。每次重试都撞在同一个错上。

**对应的问题：**
- **#20 上游证书不受信**｜✅ 已修好 —— 每次重试都撞同一个证书错，白烧四次。

## 5. 没有权限读写缓存文件

**当时电脑报的错：**
> `permission denied`
>
> `创建缓存临时文件失败: open … permission denied`

**这句话是什么意思：**缓存目录挂在 Windows 磁盘上，存进去的文件归 root 所有、只有 root 能读。程序却用普通用户跑，于是读也读不了、写也写不了。

**对应的问题：**
- **#21 缓存文件属主错乱**｜✅ 已修好 —— 缓存文件属主是 root，程序读不了；现在容器改用 root 跑。

## 6. 内存不够，缓存还被当成坏的删掉

**当时电脑报的错：**
> `缓存文件损坏，删除后按未命中处理`
>
> `cannot allocate memory`

**这句话是什么意思：**程序把整个大缓存文件一次性读进内存，内存不够就报错；更糟的是它把「读不出来」当成「文件坏了」，直接把好缓存删掉。

**对应的问题：**
- **#16 大缓存整块读内存**｜✅ 已修好 —— 整个读进内存，爆了还删缓存。

## 7. 配置文件写错了，网址拼不出来

**当时电脑报的错：**
> `必须以 http:// 或 https:// 开头`
>
> `unsupported protocol scheme ""`

**这句话是什么意思：**配置里写模板时，程序要求它必须像个网址；另一个坑是拼出来的地址只有半截，没有 http 开头，请求直接失败。

**对应的问题：**
- **#6 配置语义陷阱**｜🟡 修好一半 —— 部分写法已放行，缺字段还是不吭声。
- **#7 入站 Host 未参与匹配**｜✅ 已修好 —— 地址拼成半截、域名没参与匹配，都改了。

## 8. 该不该用缓存判错了（Range / 304 / 可变的标签）

**当时电脑报的错：**
> `reason=request-range`
>
> `status=304 body_bytes=0`
>
> `descriptor is neither a manifest or index`

**这句话是什么意思：**该用缓存的没走缓存，该去问上游的又拿了旧内容：带「从第几字节开始」的请求被判成不缓存，回「没更新」的请求被当成失败，标签这种会变的东西被当成永不变。

**对应的问题：**
- **#2 Range 起点被判旁路**｜✅ 已修好 —— 带断点请求就绕开缓存，大层永远下不完。
- **#12 弱 ETag 与 304**｜✅ 已修好 —— 「缓存还没过期」被判成失败，命中不了。
- **#19 可变目标被缓存**｜✅ 已修好 —— 会变的内容被缓存，docker 拿到旧东西。

## 9. 代码和打包本身有问题

**当时电脑报的错：**
> `package proxy-cache/cache is not in std`
>
> `WARNING: DATA RACE`
>
> `should be a string or a slog.Attr`
>
> `short read: expected 129306884 bytes but got 0: unexpected EOF`

**这句话是什么意思：**这几条不是线上流量，而是代码和打包本身站不住：打包时把源码一起排掉了、日志少写一个符号编译不过、两边同时读写同一块数据，还有续传时半截文件打不开。

**对应的问题：**
- **#11 slowMerger 并发竞态**｜✅ 已修好 —— 一边在读、一边被清空，数据就断了。
- **#14 日志规范**｜✅ 已修好 —— 少个符号编译不过，日志键名也不合规。
- **#15 构建与部署事故**｜✅ 已修好 —— 打包漏了源码、换了用户写不进缓存。

## 10. 电脑环境坏了（挂着 Windows 磁盘 / `/dev/null` 被换掉）

**当时电脑报的错：**
> `aname=drvfs`
>
> `-rw-rw-rw-    1 root     root           167 Nov 20 16:17 /dev/null`

**这句话是什么意思：**不是程序写错，是机器环境坏了：缓存目录其实挂在 Windows 的 D 盘上（一种叫 9p 的跨系统共享盘，大文件读写不稳）；同一天连「黑洞文件」`/dev/null` 都被换成了普通文件。

**对应的问题：**
- **#17 缓存目录在 9p 盘**｜🟡 修好一半 —— 缓存放在 9p 上，大文件读写不稳。
- **#18 /dev/null 被换成文件**｜✅ 已修好 —— 黑洞文件变普通文件，工具一写就满。

## 11. 没有报错的问题（只是慢 / 看起来像坏）

**当时电脑报的错：**
> `预取 blob 回源失败`
>
> `为什么缓存的文件，查看是乱码的，这样你确定能用于下次吗`
>
> `ttl 0 就是无过期时间`

**这句话是什么意思：**这两条没有真报错：一条只是慢（同一层下载了两遍），一条是用户打开缓存文件看到乱码，怀疑它坏了——其实那是压缩后的正常样子。

**对应的问题：**
- **#8 预取搭车重复下载**｜✅ 已修好 —— 同一层被下了两遍，白白慢一倍。
- **#13 TTL 与 gzip 回放**｜✅ 已修好 —— ttl:0 被偷偷改成 30 分钟，乱码其实正常。
